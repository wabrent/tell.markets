## Почему меняемся

Запуски, которые делают 100–500k капы за пару дней, устроены одинаково:
1. **Рабочий продукт** (приложение, CLI, API), а не лендинг.
2. **Токен = доля в выручке**: выкуп/сжигание/стейкинг, всё видно on-chain.
3. **Подключение к агентам**: MCP-сервер и оплата по x402 (Kyte, Zolva, Texel).
4. **Открытый код и страница «proof/verify»** с адресами и транзакциями.

Пример: Letronna (LETRO) — за 4 дня $296k капы, 629 холдеров, 6 740 сделок, выпуск на Uniswap v4 через ~7 часов после запуска, создатель заработал $27k на комиссиях Pons.

Tell сейчас — сайт для людей, а у будущего $TELL одна польза: безлимит проверок. Этого мало.

**Новая позиция:** Tell — проверка риска токенов Robinhood Chain **для торговых агентов и людей**. Агенты (Zolva, Autopilot у Kyte и т.п.) покупают токены сами — им нужен быстрый ответ «опасно / нет» перед сделкой. Платят за проверку через x402 в USDG, часть выручки — в выкуп и сжигание $TELL.

## Фазы

### Фаза 1. Быстрый публичный API (2–3 дня)
Агенту нельзя ждать 30 секунд.
- `GET /api/v1/check?token=0x…&mode=quick|full` — компактный JSON: `score`, `label`, `critical[]`, `flags[]`, `verdict`, `checkedAt`, `reportUrl`.
- **quick** (≤3 с): из кэша, иначе только контракт + рынок + деплоер (без полной истории переводов и AI).
- **full**: текущая проверка целиком (~30 с), с кэшем.
- Фоновый наблюдатель запусков уже проверяет новые токены Pons → большинство запросов отвечаются из кэша мгновенно.
- `GET /api/v1/launches`, `GET /api/v1/compare?a=…&b=…`.
- Страница `/docs` (описание API, примеры для curl/JS/Python).
- **Платный RPC** (QuickNode / Chainstack / Dwellir): без него quick-режим не будет стабильно быстрым.

### Фаза 2. MCP-сервер (2 дня)
- Удалённый MCP по адресу `https://tell.markets/mcp` (Streamable HTTP, `@modelcontextprotocol/sdk`).
- Инструменты: `check_token`, `quick_check`, `compare_tokens`, `recent_launches`, `explain_flags`.
- Открытый репозиторий `tell-mcp` на GitHub + инструкция «подключить к Claude / Cursor / своему агенту».

### Фаза 3. Оплата x402 в USDG (3–4 дня)
- Без оплаты: quick — бесплатно с лимитом; full — несколько в день.
- С оплатой: full ≈ $0.02–0.05 за проверку (цены уточним).
- Сервер отвечает `402` с требованиями оплаты: схема `exact`, сеть `eip155:4663`, актив USDG, получатель — казна Tell. Агент подписывает платёж и повторяет запрос с заголовком оплаты.
- Проверка и списание: свой минимальный фасилитатор на viem (кошелёк на сервере платит газ) **или** готовый открытый (см. «Источники»). Сторонние фасилитаторы пока без аудита — сначала проверить, какой стандарт поддерживает USDG на Robinhood Chain (EIP-3009 или только Permit2), и адрес USDG прямо в сети.
- Держатели $TELL (после запуска токена): вход подписью кошелька (уже есть в `src/auth.ts`) → API-ключ → бесплатные/дешёвые проверки.

### Фаза 4. Новые проверки «обещания против блокчейна» (3–4 дня)
То, чего нет ни у кого и что сейчас реально нужно:
- **Выкуп и сжигание:** сайт обещает buyback/burn → ищем переводы на burn-адреса и покупки с казны; нет транзакций → флаг.
- **Аудит:** «аудит пройден» в одном месте и «не аудирован» в другом (как у Tidewell) → флаг противоречия (дописать в AI-разбор сайта).
- **Лаунчпад:** ссылка на покупку ведёт на настоящий домен Pons, а не на двойника (на сайтах встречаются и `ponsfamily.com`, и `pons.family` — выяснить, какой настоящий, остальные помечать).
- **Живой ли продукт:** приложение открывается, GitHub обновлялся недавно (API GitHub), контракты протокола имеют активность on-chain.
- **Доход создателя:** сколько создатель уже заработал на комиссиях и вывел ли.

### Фаза 5. Журнал вердиктов on-chain и страница /proof (2–3 дня)
- Простой контракт на Robinhood Chain: раз в час записывает хэш (Merkle-корень) всех выданных вердиктов.
- `/proof`: адрес контракта, транзакции, выручка x402, транзакции выкупа/сжигания $TELL.
- Любой может проверить, что Tell не переписывает оценки задним числом.

### Фаза 6. Боты и охват (2–3 дня)
- X: автопост по каждому заметному запуску на Pons + ежедневно «Запуски дня» (топ чистых / топ подозрительных). X API платный — заложить расходы.
- Telegram: бот `/check 0x…` и канал с лентой запусков.

### Фаза 7. Запуск $TELL на Pons (после фаз 1–3, когда API и оплата работают)
- Запуск с рабочим продуктом: MCP, API, оплата, /proof.
- Токеномика (прозрачная, on-chain):
  - часть выручки x402 → выкуп и сжигание $TELL, транзакции на /proof;
  - держателям — бесплатные проверки для своих агентов, алерты, ранний доступ к новым проверкам;
  - комиссии создателя с Pons → казна проекта (на развитие и RPC/AI).
- Никаких обещаний дохода, «Not financial advice» везде.

## Сроки
Фазы 1–3 ≈ 1.5 недели — после этого уже можно запускать токен. Фазы 4–6 ≈ ещё 1–1.5 недели, можно параллельно с запуском.

## Что нужно от владельца
1. **Адрес казны** (кошелёк, куда идут оплаты; только публичный адрес, ключи никому).
2. **Платный RPC** (~$50/мес) — ключ вписать в `/opt/tell/.env` на сервере.
3. Решение по **ценам** проверок.
4. Какой домен Pons настоящий.
5. Позже: аккаунты X / Telegram для ботов, бюджет на X API.

## Риски
- Сторонние x402-фасилитаторы без аудита; свой фасилитатор = горячий кошелёк на сервере (держать там только газ).
- Скамеры подстраиваются под проверки → веса на сервере, регулярные правки.
- Расход AI растёт с трафиком → кэш, quick-режим без AI, платный full.
- Ошибки оценки → показывать причины каждого флага.
